If you want to install any special software (a newer version of R, libraries for
spatial or bioinformatic data analysis, etc.), the best way to do this is
through containers. Containers sound complicated but they're actually fairly
straightforward to use.

# Downloading a pre-built container

There are lots of pre-built containers; you can browse through them at [Docker
Hub](https://hub.docker.com). For example, if you just want the latest version
of R:

```bash
apptainer pull docker://rocker/r-ver
```
{: .prompt}

If you want a specific version:

```bash
apptainer pull docker://rocker/r-ver:4.5.0
```
{: .prompt}

If you want one that comes with all the tidyverse packages installed:

```bash
apptainer pull docker://rocker/tidyverse
```
{: .prompt}

If you want one that comes with Bioconductor:

```bash
apptainer pull docker://bioconductor/r-ver
```
{: .prompt}

And so on.

This will great a (pretty big) file called something like `r-ver_latest.sif`
(depending on which container you pulled). This is known as an image file, and
contains a miniature operating system with the latest version of R installed
(plus any extras, as requested).

# Running a program on the 

Once you have the image you want, you can start an interactive session inside
the container with:

```bash
apptainer shell r-ver_latest.sif
```
{: .prompt}

This is useful for debugging, as you can see what it looks like inside the
container, what packages are available, etc. MORE

When it's time to run a script through the container, simply:

```bash
apptainer exec r-ver_latest.sif Rscript sim.R
```
{: .prompt}

# Customizing your container

The basic format is this:

```
Bootstrap: docker
From: bioconductor/r-ver:3.23

%post
    # Install system dependencies
    apt-get update && apt-get install -y \
        git

    # R packages
    Rscript -e 'install.packages(c(
        "data.table",
        "ggplot2",
        "R.utils"
        ), repos = "https://cloud.r-project.org"
    )'

    # Python packages
    python3 -m venv /opt/venv
    /opt/venv/bin/pip install docopt

%environment
    export PATH=/opt/venv/bin:$PATH
```

# Containers

Learning to use containers is a bit more complicated, because they add an additional "layer of abstraction". 
You can roughly imagine containers as providing a virtual environment you can work in with a 
separate set of installed programs and only limited ability to interact with the host system. 
Containers can be defined declaratively via configuration files, which is a helpful feature for 
reproducible computing. They are a key building block for a lot of cloud computing in industry. 

For use on HPC, we're not usually interested in more complicated containerized 
development patterns (e.g., container orchestration); instead we usually just want 
a convenient way to get the software we need running in a scalable environment. 
As such, this tutorial will keep things pretty basic, but but a fuller treatment 
can be found elsewhere. Here are a few links to get you started:

* [Docker](https://docs.docker.com/get-started/introduction/): a popular containerization tool which supports multiple platforms. 
* [Docker (wikipedia)](https://en.wikipedia.org/wiki/Docker_(software)): a Wikipedia page with a good history and summary of containers
* [Podman](https://podman.io/docs): a more recent alternative to Docker that is gaining widespread adoption.
* [Apptainer](https://apptainer.org/): the containerization tool which is used on the Argon HPC system (the more widely adopted Docker and Podman container images can be converted to work with Apptainer)
* [The Rocker Project](https://rocker-project.org/): A project collecting pre-made images for the R environment. 

## Getting access to prebuilt container images

While containers allow us a ton of flexibility, it's actually easier for many 
typical workflows to start with a pre-built image rather than to define our own. 
As most Biostatistics students work in R, we'll focus on images provided by
[The Rocker Project](https://rocker-project.org/).

### Step 1 - Pull down the image you want

Here, we're going to pull down the [tidyverse](https://hub.docker.com/r/rocker/tidyverse/) package,
because it has a ton of dependencies, and often causes installation issues. 

The following command uses the `apptainer` program to create a new file, called `tidyverse.sif` 
in your current directory. This file is of "singularity image format", the native
image format for apptainer. The new image file will be created from
the docker image hosted online. 

```bash
apptainer pull tidyverse.sif docker://rocker/tidyverse:devel
```
{: .prompt}

### Step 2 - Open a shell in your container

To open a shell, you just need to do:

```bash
apptainer run ./tidyverse.sif /bin/bash
```
{: .prompt}

Then, you can open R in the usual way:

```bash
R
```
{: .prompt}

Similarly, you can exist out and back into your regular environment in the usual way:

```bash
exit
```
{: .prompt}

More commonly, you'll want to make sure the container can access and make changes
to files you have permission to modify. One way to accomplish this is
by using an `overlay`, or a directory to store changes (which don't otherwise persist). 

```bash
mkdir tidyverse.overlay
apptainer run --overlay tidyverse.overlay ./tidyverse.sif /bin/bash
```
{: .prompt}

If you do this, you can install packages from within R in the usual way
with `install.packages` and still have access to them later (changes won't usually persist). 

## Building your own containers

To build a custom container, the most general way is to use a different computer
with access to Docker or Podman, and build a container there. Then, you can copy the `sif` file
to Argon, and interact with it in the usual way. 

We have put together some example scripts and a brief Readme on how to do so
in [this repository](https://github.com/IowaBiostat/hpc-apptainer)
